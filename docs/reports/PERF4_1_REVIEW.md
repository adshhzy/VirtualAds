## 下一轮的优先顺序

1. **先建立真实业务 A/B 和明确下游输出需求。** 保持 legacy 几何/索引、alpha、素材版本规则；记录共享准备到 NumPy 返回、编码和发送、完整服务的均值/P95。
   基准中的运动估计、sigma 和 Gaussian 回调仍是合成定义，不能替换生产方法。补充真实 bbox/ROI 尺寸变化、镜头切换和实际核尺寸的输入回放；当前共享基准主要改变矩阵/标定数值，不能代表所有动态布局。
2. **输出链路：约 1.9 ms 是已测出的明确成本。** 如果下游能接收 GPU Tensor，可直接对接 GPU 编码，另测编码端成本；如果仍必须返回立即可读的 NumPy，回传不能凭空取消。
   异步流水线需要增加事件/完成句柄和缓冲生命周期约定，主要改善吞吐，未必同幅减少单帧延迟。不可简单删同步，也不可覆写调用方持有的输出。
3. **固定 NumPy 接口下，重点研究全图处理。** 畸变采样与两段模糊/融合约 1.78 ms，另有清零约 0.25 ms。B8/1080p 的每张 FP32 RGBA 中间图约 265.4 MB。
   可实验分块、halo 和部分阶段融合，或保守裁剪受广告影响的区域；必须计入畸变、滤波边界、重叠覆盖和零填充。
   复用 workspace 仅节省分配，并不会自动消除内存读写；融合也可能因重复采样/寄存器压力变慢。先做可回退原型，再用同轮输出校验及延迟确认。
4. **降低提交与 Python 准备成本作为较小的独立实验。** ROI grid + warp 仍可融合以减少 16 次 launch 和中间 grid，但网格算术本身只约 0.024 ms，不能承诺靠它省数毫秒。
   同时可缓存稳定的布局解析，避免每帧重复组织元数据；K/系数/矩阵/透明度的当前值和素材失效机制必须保留。

不再优先投入：扩大零命中的 sigma 缓存、再次批量上传已经打包的 16 个矩阵、再次把已经共享的 prepare 移出循环。
连续 sigma 下缓存 0/100 是预期现象；量化 sigma 会改变画面语义。直接 GPU 生成 Gaussian 因子需先拿到真实回调公式，不能从合成 fixture 推定。

性能实验每次只改变一项，保持 NumPy 输出独立性、B1 HWC/B多 BHWC、uint8 差 ≤1、网格差 ≤2e-6；先正确性再计时。
至少保留多个交错顺序的对照轮次，新增收益不足以超过波动时不作为默认优化启用。
